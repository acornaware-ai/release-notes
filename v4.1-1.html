Juttu v1.0.2 — v4.1-1「数字生命架构升级」

build 2 TestFlight 已上 对应 PRD v4.1-1
TL;DR · 30 秒读完

这版做了一件结构性大事：把 v4 时代「角色被 cron 推着生成内容」的流水线工人模式，重写成「角色每天醒来，自己看一眼世界、自己出去逛逛、消化一下、再回来分享」的因果链路。

同时清掉 v4 上线后用户测试反馈的 6 个体验粗糙点（详情页、Recap、Quote 太长、Prep 不够具体、下拉刷新无效、Snippet 看不到）。

📦 工程量：23 个 PR（PR-9.0 → PR-9.22），后端 +384 测试，iOS +36 测试

核心改造：数字生命链路

从 v4 的「单线程 cron 推内容」改成 5 stage 因果链路：

🌅 Stage 1 · Exploration（06:30 UTC）
角色「出去逛」——LLM 生成搜索意图（"今天我想看什么"），调 Tavily API 抓回 1-3 篇外部网页，source="exploration" 入库。补 RSS / Reddit 之外的"主动找"信号。
🧠 Stage 2 · Perception（06:50 UTC）
角色「消化」——拉今天的 24h scored signals + LLM 分别从 Nova / Leo 视角写「读后感」，存入 perceptions collection（含 what / curiosity / want_to_share / signal_id，防 LLM 幻觉 signal_id）。3 天 GC。
📰 Stage 3 · Trending Generation（07:00 UTC）
话题卡生成，主要消费 perceptions 而非原始 signals——卡片读起来像"角色刚消化完跟你分享"而不是"机器人在播报新闻"。
📋 Stage 4 · Recap Generation（用户 /exit 触发）
用户聊 ≥5 轮后退出 → 后端生成 Recap → 写入 recap_cards（(user_id, topic_id) 唯一索引 + next-day UTC 0:00 过期）。
🌙 Stage 5 · Dream Agent（04:00 UTC）
凌晨更新 latest_memory.json + 决定生成 return card（feed 顶部"你前两天聊到的话题"卡）。

6 个体验粗糙点修复

问题修复
详情页之前不存在，点卡直接进 chat 扣配额 新加详情页，opening_content 渲染气泡，CTA 才扣配额（详情页本身免费）
Recap 没有 detail 视图 新建 RecapDetailView，CTA "Continue this conversation" 创建新 session
Quote 太长（≤150 字符在 feed 上一行装不下） 收紧到 ≤100 字符
Prep 卡片太抽象（"试试问问他"） prompt 要求"具体名字 / 数字 / 可以直接说出口的话术"
下拉刷新无效 Home feed 加 .refreshable + 后端 ?refresh=true 限流 query param（默认 3 次/slot）
Snippet 用户看不到 client-side seen ack（/feed/snippet/seen POST），避免后端把"返回"误判为"已看"
