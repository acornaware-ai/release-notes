Juttu v1.0.4 — v4.3「voice tone + 架构清理」

build 9 TestFlight 已上 对应 PRD v4.3
TL;DR · 30 秒读完

这版不是新功能——是「调子」改造 + 数据库重构。

三角色说话从「专栏作家调」变回「朋友顺嘴说」；数据库字段大改名（用户看不到）；UI 故意保持不变。

用户反应「跟之前差不多」是正常的。视觉稳定是设计意图，voice tone 是统计意义的「调子」，不是 push 通知那种立刻可感的事。

📦 TestFlight 上只装 build 9（4-8 是 hotfix 中间态）

① AI 说话调子更朋友化

三个角色的人设描述深度洗了——删掉「策展人」「筛一圈带回来」这些内容生产者叙事，改成「她们活在自己客厅，user 偶尔路过加入」的状态描述。写卡片前要求 AI 先想另外两人会怎么接、用户此刻想听什么。

改造前 · 像编辑总结
"高温下个人的活儿还能勉强凑合，但团队协作会率先瓦解。热浪里，最先蒸发的是对同事的耐心。"
目标 · 像朋友连发
"我刚看到一个特别扎心的研究 / 气温升高的时候，最先瓦解的不是个人产出 / 而是团队的『协作感』"
实验室指标改造前改造后

⚠️ 诚实告诉产品：lab 跑出来这么漂亮的数据，但部署后从线上拉的卡片看 AI 实际输出仍偏「专栏作家调」，没复现 5× 改进。可能因为 lab 跟 prod 用的 LLM 不同 / voice tone 单看一两张感觉不出统计差异。

工程建议：先观察 2 周用户反馈，再决定要不要追加 few-shot 示例改造 prompt（详见 admin 后台 Q-4）。

② 数据库字段大改名（用户看不到）

原字段名 quote / tag / opening_content 在 AI 看来是「制作可被引用的内容、给内容打分类标签、提供预览段落」——直接 prime AI 进入「产出社媒卡片」模式。改名后 AI 看到的是「朋友聊天的记录」。

旧字段新字段类型变更
nova_quotenova_said字符串 → 1-3 条短消息列表
nova_tagnova_mood≤16 字符（含 hotfix）
opening_contentexchange不变
field_tags删除—
want_to_share删除—

v4.2 老数据已重命名带 _v4_2_backup 后缀保留，可随时回滚（详见 admin Q-6）。

③ UI 视觉故意保持稳定

这是 PRD §4.6 明确要求：feed 单 quote 视觉跟 v4.2 一模一样，详情页对话气泡不变，mood chip 跟 tag chip 视觉位置 / 字号 / 颜色都没变。

v4.3 想验证的是「调子」是否能涌现，UI 改动会引入混淆变量。如果 voice 在 v4.4 稳定下来，再考虑 UI 是否要跟着调。

发版当天的两个 Hotfix

🟢 mood 英文截断已修
线上 AI 输出 mood 全是英文截断词（Reflecti / Pragmati）。PRD §5.6 字面写「≤8 字符」是中文场景中心，英文不够装。修法：上限放到 16 字符 + prompt 加双语示例引导。线上验证全是完整词。需要产品决定 PRD §5.6 是否字面 amend（admin E-6）。
🟢 iOS 详情页返回按钮已修
用户报「点详情页返回 chevron 第一次没反应，第二次能返回」。工程追 4 个 PR 在 SwiftUI 框架内部猜原因，全错。User 一句「我怀疑是按钮点击事件的问题」让工程加 print 验证，发现 button 根本没接收 tap——最基础的 hit-test 问题。chevron 视觉 18×18px，Apple HIG 要求最低 44×44px。差 2.4×，用户手指偏一点就 miss。已加 44×44 标准点击区域 + 30 次循环自动化测试防回归（详见 admin D-3）。

5 分钟验收 demo path

  1. 打开 app → feed 加载（30 张 trending + snippets）
  2. 看一张卡：mood chip 必须完整词（认真/好奇/playful/curious），不能是 Reflecti 半截词
  3. 点卡进详情页 → 3-5 条对话气泡
  4. 点左上返回 chevron → 第一次点应立刻返回（不是要点两次）
  5. 试弹药库 Path A：详情页 → Save to Ammo → navbar tray 图标 → 列表里能看到
  6. 试聊天：详情页 → Chat with them → 进 chat 应有 1-2 条开场消息

如果 ② 或 ④ 异常，说明装的不是 build 9。
