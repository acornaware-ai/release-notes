② 新模块：弹药库

用户自己的收藏空间。两条存入路径：

🎯 路径 A — 聊前存
详情页底部按钮从单个变两个并列——「Continue（黑）」+「存到弹药库（蜂蜜色）」。点存 → 立刻看到 toast「已存入弹药库」（AI 后台慢慢浓缩，用户不用等）。
💬 路径 B — 聊后存
聊到 ≥3 轮后点左上 ← ，弹一个对话框：「这次聊得不错。要不要把它浓缩存进弹药库？」选「浓缩存」就把这次聊的内容织进弹药卡。

进入入口：navbar 加蜂蜜色 🗃️ 图标，点进去看极简密集列表——一行 78pt，标题 + 一句话说明 + 来源带颜色 + 相对时间。

弹药卡内容：标题 ≤18 字、一句话说明 ≤80 字、来源标注（「Nova」聊前存 / 「Nova + 你」聊后存）。

点弹药卡：如果原聊天还活着 → 直接接着聊（不扣配额）；否则走正常 paywall。

③ Recap 触发条件改写

v4.1 行为：聊 ≥5 轮自动产 Recap，1-2 天后回流。
v4.2 行为：只有「聊了 + 主动存了」（路径 B）的弹药卡，才会 24-48 小时后产 Recap。

  • 路径 A（只存没聊）→ 不产
  • 没存的聊 → 不产

Recap 措辞要求 AI 自然带出关联：「你前两天存的那张『完美是排外的』，后来还接着聊了一会儿——」

为什么改：v4.1 的「≥5 轮」门槛太低，产了大量「用户其实并不在意」的 Recap，回流转化稀。改成「让用户用行为投票」后噪音应该明显下降。

Build 3 紧急修复（E-5）

🟢 弹药库 / Recap 进聊天看不到对话历史
2026-05-08 真机暴露：用户重装 app 后从弹药库 / Recap / 详情页 CTA 进 chat 看到空白对话——之前跟 Nova 聊的 N 轮 history 没人去拉。根因：iOS 三处 RESUME 路径都依赖本地 cache 重装清零；fallthrough 到 POST /chat 时后端只认 active session，5/7 早已被 cleanup_idle 改成 completed。三层修复（PR-10.x）：iOS Path B 直接 navigate（用 ammo.sourceSessionId）+ 后端 prefer_resume_completed 参数 + POST /chat/{id}/messages 自动激活 completed session。
